# lazr — строить Rust-приложения моделью, а не файлом

## Когда применять

- нужен GUI на Rust, который агент может менять точечными операциями;
- экран надо описать данными (модель), а не «напиши main.rs целиком»;
- нужна проверка интерфейса без экрана: собралось, нарисовалось, обработчики не падают.

## Цикл

```bash
lazr new DIR --title "Заголовок" --size 900x720
lazr state DIR count int 0
lazr add DIR label "Нажатий: {count}"
lazr add DIR button "Плюс" --do "count += 1" --style "icon:play, key:ctrl+plus"
lazr verify DIR          # сборка + кадр без окна + вызов всех действий
```

Модель в S-выражениях (когда форму строит программа, а не человек):

```bash
lazr lisp examples/paint.lisp --to /tmp/paint   # S-выражения → модель → код
lazr lisp examples/paint.lisp                    # только текст модели
```

Для агента по MCP: `form_new`, `form_state`, `form_add`, `form_show`, `form_widgets`, `form_generate`,
`form_build`, `form_headless`.

## Правила, без которых не собирается

1. **Проверка — три факта.** «Работает» подтверждается `lazr verify` (сборка + кадр без окна + прогон
   действий), а не текстом сгенерированного кода. Покажи вывод команды.
2. **Стиль идёт после действия.** `button "x" do count += 1 {key:ctrl+s}` — да; `{…}` до `do` — нет.
3. **float — это f32.** В модели `state size float 4` печатает `4.0`; руками `4` в Rust-коде не пиши, egui ждёт f32.
4. **Сложное — в `rust-widget`, а не в насилие над DSL.** Методы, списки, доступ к `ui` — только там. Такой код
   проверяется кадром (`--headless`): паника видна сразу.
5. **Сырые строки для Rust.** В S-выражениях `"""…"""` — без экранирования кавычек; в строчной модели используй
   блоки `rust widget NAME { … }`.
6. **Своё состояние — `rust field`.** `(rust-field strokes "Vec<Stroke>" "Vec::new()")`; структура объявляется в
   `rust-item`/`rust fn` на уровне модуля.
7. **Общий target dir.** `LAZR_TARGET_DIR` (по умолчанию `~/.cache/lazr/target`) — иначе egui пересобирается на
   каждом шаге и цикл агента стоит минуты.

## Раскладка и тема

- Абсолютное место: `place 800x480` + `at 16 50` + `size 240x170`; якорь — `anchor right bottom at 16 16`
  (точка от правого/нижнего края). В S-выражениях: `(place 800 480 (vbox :at 16 50 :box 240 170 …))`;
  `:at`/`:box` принимают и пару чисел, и список.
- Тема — одна строка: `theme dark accent:#388bfd font:15 spacing:10 round:8`; компилируется в
  `fn apply_theme(ctx)` и применяется и в окне, и в головном кадре, поэтому тоже проверяется.
- В строчной модели `do` заканчивается на `at`/`size`/`anchor`/`->`/`{стиль}` — не съедай действие этими словами.

## Упаковка

`lazr package DIR [--release]` → `dist/`: бинарь, `icon.png` (rsvg-convert из docs/logo.svg), ярлык
`.desktop` с `Name` из заголовка модели, tar.gz. Установщика и подписи нет — так и говори.

## Иконки и шрифты

- Глифы берутся из шрифтов egui; без `monochrome_emoji_fonts` у egui все эмодзи — tofu. В генерируемом
  Cargo.toml этот фича включена.
- Не всякий глиф есть в шрифте: стрелки, ⌂, ▭, ◯, ╱, ▣ дают пустые квадраты. Набор иконок ограничен
  проверенными именами (save, open, delete, undo, play, check, close, star, warn…).

## Проверяй функцию по эффекту, а не по вызову

«Действие: ok» в `--selftest` значит только то, что код не паниковал. Это **не** проверка корректности.
Каждая функция собранного приложения проверяется по наблюдаемому эффекту, и в отчёте указывается, чем
именно эффект подтверждён:

| Функция | Что должно произойти | Чем подтверждать |
|---|---|---|
| заливка | закрашен **замкнутый контур под кликом**, а не весь холст и не фон | до/после скриншот + проверка, что пиксель вне контура не изменился |
| сохранение | файл создан, непустой, читается обратно и даёт то же состояние | путь, размер, round-trip: сохранить → очистить → открыть → сравнить |
| открытие | вызывается системный диалог выбора файла (или честное сообщение, что его нет) | лог процесса/тип вызова + отсутствие «молчаливого nothing» |
| отмена | возвращает **точно** предыдущее состояние, повторный откат идёт дальше вглубь | счётчик шагов до и после, сравнение состояния |
| рисование | штрих появляется в точке указателя и в цвете/толщине инструмента | скриншот + счётчик штрихов/точек |
| слайдер/чекбокс/поле | связанное поле состояния меняется | значение в статусе/`show` до и после |
| горячая клавиша | срабатывает без фокуса на кнопке | событие клавиши через `xdotool key`, затем эффект |
| тема | шрифт, акцент и скругления реально применены | сравнение кадра с темой и без |

Правила:

1. **Нет эффекта — нет «работает».** Если проверить нечем, это пишется как непроверенное, а не как готовое.
2. **Один эффект — одно доказательство.** Нельзя закрывать три функции одним «сборка прошла».
3. **Проверяй на границах**: пустой ввод, максимум/минимум, отмена посреди операции, отсутствующий файл,
   повторный клик, изменение размера окна.
4. **Скриншот — тоже данные**: сохраняй в репозиторий (`docs/…png`) и смотри на него, а не только на число фигур.
5. Для UI-проверок используй скилл `adversarial-ui-test` (атаки на контролы и инвентарь доказательств).
6. **Диалог — не единственный путь.** Системные диалоги (zenity/GTK) не принимают синтетический ввод, поэтому
   у приложения должен быть путь + хоткей («записать по пути», «прочитать по пути»): тогда эффект проверяется
   файлом и пикселями, а диалог остаётся удобством. Проверяй оба пути и пиши в отчёте, какой подтверждён.
7. **Модификаторы в скриптах.** `xdotool key --window` теряет модификаторы; надёжнее активировать окно
   (`windowactivate --sync`) и слать клавиши глобально. Для проверок предпочитай одиночные клавиши (F5/F6/F7).

## Границы, которые надо называть вслух

Нет якорей и абсолютных координат, нет шрифтов/тем, нет вызовов функций в обработчиках, нет встроенной истории
модели и упаковки. Если задача упирается в это — говори прямо, а не изображай, что модель всё умеет.

## Рантайм и генератор

`lazr live FILE` читает модель на ходу: правишь файл — окно меняется без пересборки. Проверяй его так же, как
сгенерированное приложение: `lazr live FILE --check` применяет каждое действие и печатает изменения полей.
Действие, которое «не меняет ничего», — это дефект разбора, а не норма: в рантайме эффект не должен забирать
в себя хвост строки (стиль `{…}`, привязку `->`).

## Живой пример

`examples/paint.lisp` — Paint: 8 инструментов, палитра, отмена, сохранение, горячие клавиши. Модель ~50 строк
форм, остальное — один `rust-item` с холстом.

## Тема, стили и глифы — три вещи, которые ломаются чаще всего

- **Строку стиля копируют в модель как есть.** Форма темы принимает `accent:#00a2e8`, `:accent "#00a2e8"`
  и `(accent "#00a2e8")` — все три дают одно. Числа (`font:14`, `round:12`) читаются и из строки.
  Строки стилей живут в `skills/design-styles/SKILL.md` (42 стиля).
- **Фон окна рисует сама программа.** `eframe 0.37` отдаёт голый `Ui`, поэтому кодогенератор красит
  `ui.max_rect()` цветом `panel_fill` до отрисовки виджетов. Без этого светлая тема выглядит чёрной,
  и это не баг темы — это отсутствующий фон.
- **Иконка в кнопке — кодемпоинт.** `button "" … :icon "\uf04b"` даёт компактную кнопку-глиф из
  подключённого `icon-font`; подпись должна быть пустой. `when … else` держит одну кнопку play/pause
  видимой в каждый момент — два состояния в модели выражаются двумя ветками, а не переключением иконки.
- **Условие может быть полем-флагом.** `if playing { … }` и `(if playing …)` работают без сравнения.
- **Ползунок значения не дублирует** (`show_value(false)`): число пишется подписью в модели, если нужно.

## Окно — тоже модель, и проверять его надо руками

- **`chrome:own` снимает системную рамку.** Тогда полосу заголовка рисует сгенерированный `titlebar()`:
  `ViewportCommand::StartDrag` на перетаскивание, крестик из двух линий на закрытие. Крестик рисуем линиями,
  а не глифом, — иначе без шрифта иконок получится тофу.
- **Раскладку и рамку нельзя смешивать наугад.** Своя рамка занимает 30 px сверху (`ui.add_space`), поэтому
  контент под ней начинается ниже; при `drag-anywhere` перетаскивание вешаем на `ui.max_rect()` ДО виджетов,
  иначе кнопки перестают нажиматься.
- **Правило проверки:** «окно открылось» — не проверка. Проверка — клик по своему крестику завершает процесс
  (`pgrep` пуст), а сама рамка видна на скриншоте.
- **Размер окна можно писать двумя числами** (`window "Т" 420 300`) или через `x` (`420x300`) — разбор
  обязан понимать оба, иначе параметры окна уедут в ошибку «не параметр».
- **Опции окна должны пережить конвертацию.** `.lisp → .lazr` идёт через `model::render`, поэтому каждый новый
  ключ окна нужно писать и в `render`, и в парсеры обоих синтаксисов, и в рантайм (`WindowFlags`).
- **Центрирование — один раз, а не каждый кадр.** `monitor_size` приходит не сразу, поэтому позицию ставим по
  флагу в `ui.data` (`lazr:centered`), иначе окно дёргается, если пользователь его сдвинул.

## Шрифт, моно и подсказки

- **Свой шрифт ставится первым в proportional** (`FontPriority::Highest`), встроенный остаётся запасным —
  так кириллица и редкие глифы не превращаются в квадраты. Путь к TTF — строка модели, не константа.
- **Кавычки внутри стиля — часть токена.** `{hint:"два слова"}` обязан остаться одним токеном, иначе
  токенизатор выкинет текст в действие и парсер скажет «ожидалась «;»». Проверять это тестом
  `style_with_quoted_value_is_still_style`.
- **Стиль распознаётся по известным ключам, а не по наличию «:»** — иначе `{ name = "a:b" }` станет стилем.
- **Подсказка — стиль, а не аргумент:** `{hint:"…"}` у подписи и у кнопки; у кнопки с горячей клавишей
  подсказка по умолчанию — сама клавиша.
- **Моно включается у виджета** (`{mono}`), а не глобально: в одном окне терминал и обычный текст живут рядом.

## Состояние между запусками

- **`store "путь"`** — единственная строка, которая делает приложение полезным: поля читаются при старте и
  пишутся при изменении. Без неё любое «сохранил» — ложь.
- **Пишем атомарно**: временный файл + `rename`. Прямая запись поверх файла теряет данные на обрыве.
- **Проверка — двумя запусками.** Один `--selftest` ничего не доказывает: нужно увидеть `1 → 2`, затем
  `2 → 3`, и содержимое файла. То же для `lazr live --check`.
- **`~` раскрываем в `HOME`** в обоих движках, иначе модель привязана к одной машине.
- **Списки** пишем через `\u{1f}`, а не через запятую: запятая — обычный символ в тексте.
