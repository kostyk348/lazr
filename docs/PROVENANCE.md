# Откуда это

`lazr` вырос не из одной записи архива, а из двух наблюдений — и это сказано прямо, без выдуманных ссылок.

1. **Традиция RAD.** Lazarus/Delphi (и до них Visual Basic) держат форму как данные: `.lfm`, `.dfm`. Человеку
   это даёт холст. `lazr` берёт только первую половину — форму как данные — и подставляет вместо холста
   именованные операции, потому что агенту холст не нужен, а дифф нужен.
2. **Наблюдение из практики агента.** «Сгенерируй main.rs целиком» ломается на опечатке в кавычках, а
   исправление одного обработчика переписывает файл целиком и прячет суть изменения. Модель + операции +
   детерминированная генерация превращают каждую правку в отдельный проверяемый факт.

Связь с «Музеем потерянных идей» (`lost-tech-museum`) — идейная: там собраны вещи, которые переизобретают
заново. RAD-среда для Rust, дружелюбная к ИИ, — как раз такой случай: Slint и Ruxel закрывают *осмотр* и
*двустороннюю правку в редакторе*, но не авторство по операциям с проверкой запуском. Конкретные записи архива
не цитируются, потому что ни одна находка не является первоисточником этой работы; правила профиля запрещают
выдумывать `id` записей.

Соседние инструменты той же серии — `stigmergy`, `chereda`, `proof`, `homeostat` — про координацию, не про UI.
